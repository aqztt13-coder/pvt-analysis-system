# دليل التشغيل والنشر المحلي (LAN) والترحيل والنسخ الاحتياطي
## نظام الإدارة المتكامل — شعبة الموائع المكمنية - قسم المختبرات والسيطرة النوعية
### PVT Reservoir Fluids Division — Administrative Management System

---

### 1. التشغيل المحلي داخل شبكة المكتب (بدون إنترنت)
1. ثبّت الحزم وابنِ الواجهة مرة واحدة على الحاسوب المركزي (الخادم):
   ```bash
   npm install
   npm run build
   ```
2. انسخ ملف `.env.example` إلى `.env` واضبط متغيرات البيئة حسب بيئة الخادم.
3. شغّل الخادم:
   - للتطوير: `npm run dev`
   - للإنتاج: `npm run start`
   - على Linux / macOS: `./run_server.sh`
   - على Windows: `run_server.bat` (وللإيقاف: `stop_server.bat`)
4. فحص الاتصال من أي جهاز على نفس الشبكة المحلية:
   - افتح المتصفح على: `http://<LOCAL_SERVER_IP>:3000`
   - فحص الحالة: `http://<LOCAL_SERVER_IP>:3000/api/health`

---

### 2. متغيرات البيئة المدعومة (`.env`)
| المتغير | القيمة الافتراضية | الوصف والسلوك |
| :--- | :--- | :--- |
| `HOST` | `0.0.0.0` | عنوان الربط الشبكي للخادم (يتيح الوصول من أجهزة الشبكة المحلية LAN). |
| `PORT` | `3000` | رقم منفذ الخادم. |
| `SESSION_SECRET` | مولّد تلقائياً | مفتاح توقيع الجلسات (32 محرفاً على الأقل). إذا لم يُحدد في البيئة، يُولّد تلقائياً مرة واحدة ويُحفظ بأمان داخل جدول إعدادات النظام في قاعدة البيانات دون إعادة توليد عشوائية عند كل تشغيل. |
| `ADMIN_INITIAL_PASSWORD` | فارغ | يُستخدم **فقط** عند التشغيل الأول على قاعدة بيانات فارغة تماماً من المستخدمين لتهيئة حساب `admin` مع إلزامية تغيير كلمة المرور (`must_change_password = 1`). لا يُعيد تعيين أو يمس حساب المدير القائم أبداً. |
| `INSTANCE_DIR` | `./instance` | مسار مجلد البيانات المفصول عن الشيفرة المصدرية. مثال Windows: `D:\PVT_Division\instance`. يُنشئ النظام تلقائياً المجلدات الفرعية `data/` و `uploads/` و `backups/` و `logs/`. |
| `BACKUP_RETENTION_COUNT` | `30` | عدد النسخ الاحتياطية المحتفظ بها. لا يحذف النظام أبداً أحدث نسخة احتياطية صالحة. |
| `AUTO_BACKUP_INTERVAL_HOURS` | `24` | الفاصل الزمني للنسخ الاحتياطي التلقائي **بالساعات** (مع منع تكرار المهام المتزامنة وتسجيل الأخطاء في `instance/logs/backup.log`). |

### 3. ترحيل قاعدة البيانات والحفاظ على البيانات (Migration V1 → V2)
عند تحديث نسخة قائمة من النظام إلى الإصدار المحسّن، يُنصح بالخطوات الآتية:
1. **أخذ نسخة احتياطية قبل التحديث**: من لوحة **إدارة النظام ← النسخ الاحتياطي والاستعادة**، أنشئ نسخة احتياطية فورية وتحقق من سلامتها (SHA-256) أو انسخ مجلد `instance/` بالكامل إلى قرص خارجي.
2. **تشغيل الخادم بعد التحديث**: ينفّذ النظام تلقائياً وضمن معاملة ذرية واحدة (`BEGIN ... COMMIT`) الترحيل V2 دون حذف أو مسح أي بيانات تاريخية:
   - تحديث اسم الشعبة الرسمي في الإعدادات إلى **شعبة الموائع المكمنية - قسم المختبرات والسيطرة النوعية** (مع الحفاظ على اسم الشركة والبيانات الأخرى).
   - تحديث مسمى `annual` من «إجازة سنوية» إلى **«إجازة اعتيادية» (Regular Leave)** مع الحفاظ على جميع سجلات الإجازات التاريخية المرتبطة به، وإضافة نوع **«إجازة خارج العراق» (Leave Outside Iraq)** (`outside_iraq`).
   - إضافة أعمدة الوجهة والسفر والمرفقات وتاريخ التقديم لجدول `leave_requests`.
   - إنشاء جدول التصنيفات المخزنية القابلة للتوسعة `inventory_categories`، وتوسيع `inventory_items` و `inventory_transactions` لدعم **المواد الكيمياوية** وسعة العبوات والحجم الكلي وحركات النقل (`transfer`) دون فقدان أي قيد أو حركة سابقة.
   - إضافة المواد الكيمياوية الخمس المعتمدة (`CHEM-001` إلى `CHEM-005`: الهكسان، التولوين، النفط الأبيض، الكلايكول، زيت الفاكيوم) باستخدام `INSERT OR IGNORE` دون المساس بالمواد الحالية.

### 4. الأمان والنسخ الاحتياطي والاستعادة
- تُحفظ كافة بيانات الإنتاج خارج الشيفرة المصدرية ضمن `INSTANCE_DIR`:
  - `data/pvt_division.db` — قاعدة بيانات SQLite بوضع WAL.
  - `uploads/` — المرفقات المشفرة الأسماء والمحمية عبر API المصادق.
  - `backups/` — النسخ الاحتياطية الموثّقة ببصمة SHA-256.
  - `logs/backup.log` — سجل عمليات وأخطاء النسخ الاحتياطي.
- قبل أي استعادة لنسخة احتياطية، ينشئ النظام تلقائياً نسخة أمان (`pre_restore`).
- **تنبيه أمني**: يجب تثبيت عنوان IP داخلي للخادم وتطبيق قواعد جدار الحماية (Firewall) لحصر الوصول بالشبكة المحلية للشركة فقط وعدم تعريض المنفذ للإنترنت العام.
